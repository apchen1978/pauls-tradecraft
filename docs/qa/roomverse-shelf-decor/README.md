## 量測方法

`node docs/qa/roomverse-shelf-decor/measure.mjs`，對分支 preview 的 4175 埠執行。Chrome、CPU 4×、固定 1440×900／390×844（手機 DPR2，產品自身上限仍為1.5）、全新 context、關閉快取、每版本一次暖機再各五次交錯量測。這輪以前一版 PR commit `db19d39` 為基準，攔截相同路徑的 app.js；確認兩版都有書架 API，首次互動時物件都還未建立，閒置載入後分別為 8 件與 11 件。

指標是點進場到初次 render 完成後 `__room` 賦值。所有次數在此刻的小物數都為零。另比對載入完成後兩版本完整請求 URL 集合，及三種指定配色的明信片像素 SHA256／尺寸。數字與前後圖見 `performance-and-parity.json` 及同目錄 QA。

| 模擬寬度 | 修改前中位數 | 修改後中位數 | 差值 |
| --- | ---: | ---: | ---: |
| 1440×900 | 1,929.8 ms | 1,716.7 ms | −213.1 ms |
| 390×844 | 1,623.8 ms | 1,653.6 ms | +29.8 ms |

兩寬度的完整載入請求集合都相同（每版 29 個 URL），沒有新圖片／模型請求。三種指定配色×兩寬度共六組明信片的尺寸與像素 SHA256 全部一致（`postcard-parity.json`）。這輪載入量測差值屬單機觀察，不把桌機負差說成效能提升，也不把手機約 30 ms 的小幅正差解讀成明顯退步。原 PR 初始版對 main 的量測記錄可在 Git 歷史中查閱；此表已改為 CC 覆核後的迭代比較。

原始明信片 PNG 保存在被 git 忽略的 `output/roomverse-shelf-decor-raw-postcards/`，避免把大量重複二進位檔放進 repo；前後對照預覽與像素 hash 提供審查。這是本機觀察，不是正式站或真機速度保證。

同一批原始 PNG 另複製到桌面 `ROOMVERSE_房門_2026-10-20/書架擺飾_原始明信片/`，供 CC 實際打開檢視。
