只補電視兩側嵌入書架，不改既有檯面。面向電視看，左架 x=+1.82、右架 x=-1.82。六格共八件，留下不對稱的空間：

| 格位 | 小物 | 實際包圍盒深度（含接觸陰影） |
| --- | --- | ---: |
| 左上 | 三本獨立薄書，藍／苔綠／陶土布面，書脊無字 | 各 8.3 cm |
| 左中 | 小木框，重用現有河景圖；有薄背板與支架 | 6.6 cm |
| 左下 | 低矮、長橢圓陶碟 | 7.7 cm |
| 右上 | 小葉植物與小盆 | 7.7 cm |
| 右中 | 薄木盒，木色與層架協調 | 9.0 cm |
| 右下 | 一本橫放薄書，保留這格最多空白 | 8.4 cm |

全部是程式幾何形成的有厚度小物（相框內容為既有 2D 圖片），不是新 GLB／照片轉 3D。重用現有木紋、牆面布紋、河景圖；新增圖片／模型檔 **0 bytes**，沒有新資產請求。

接入原有 `loadConsoleDecor()`：先等原有電視牆材質與小畫的載入／備援，再一次建立小物；首次可互動前不建立小物。材質失敗用素色實體，不讓房間失效。接觸陰影為局部薄片，始終水平，不隨斜框或平放書本轉直；這是插畫式接觸提示，不宣稱物理光線追蹤。新小物不投射遠處陰影，避免改動沙發區。

## 量測方法

`node docs/qa/roomverse-shelf-decor/measure.mjs`，對分支 preview 的 4175 埠執行。Chrome、CPU 4×、固定 1440×900／390×844（手機 DPR2，產品自身上限仍為1.5）、全新 context、關閉快取、每版本一次暖機再各五次交錯量測。攔截帶版本參數的 app.js，一次且只一次，assert 基準沒有 shelfDecor、修改版有，以免誤拿同一版本比較。

指標是點進場到初次 render 完成後 `__room` 賦值。所有次數在此刻的小物數都為零。另比對載入完成後兩版本完整請求 URL 集合，及三種指定配色的明信片像素 SHA256／尺寸。數字與前後圖見 `performance-and-parity.json` 及同目錄 QA。

| 模擬寬度 | 修改前中位數 | 修改後中位數 | 差值 |
| --- | ---: | ---: | ---: |
| 1440×900 | 2,274.8 ms | 2,279.5 ms | +4.7 ms |
| 390×844 | 2,230.2 ms | 2,164.4 ms | −65.8 ms |

本次未見載入退步；不把手機的小幅負差解讀為效能提升承諾。兩寬度的載入後請求 URL 集合完全相同，沒有新圖片／模型請求。三種指定配色×兩寬度共六組明信片的尺寸與像素 SHA256 全部一致（`postcard-parity.json`）。`before-after-1440.jpg`、`before-after-390.jpg` 提供同一畫面大小的前後陳列對照。

原始明信片 PNG 保存在被 git 忽略的 `output/roomverse-shelf-decor-raw-postcards/`，避免把大量重複二進位檔放進 repo；前後對照預覽與像素 hash 提供審查。這是本機觀察，不是正式站或真機速度保證。

同一批原始 PNG 另複製到桌面 `ROOMVERSE_房門_2026-10-20/書架擺飾_原始明信片/`，供 CC 實際打開檢視。
